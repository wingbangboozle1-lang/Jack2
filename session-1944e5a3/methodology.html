Methodology, Verification & Privacy

How this report was produced, what "verified" means here, what the site does not know, and how personal information is kept off it.

Scope & mandate

  • Asset: single-tenant quick-service restaurant (Jack in the Box), Central Los Angeles, triple-net lease, expiry window 2030–2035.
  • Question: sell before expiry, or renew — balancing wealth preservation, growth, risk (routine + black swan), and Los Angeles economic fundamentals.
  • Deliverables: this site (GitHub Pages), a line-by-line sourced findings set, flagged unverifiable items, and a decision framework with triggers.
  • Constraint observed: no manual data entry by the owner; figures drawn from official online sources only, or left blank/flagged.

Line-by-line verification protocol

  1. Every printed value was either read in an official source during this build (marked Verified) or is explicitly marked Reported / Computed / Flagged / Placeholder.
  2. Computed values show their arithmetic (e.g., +2.1% = 810.8/794.4−1; −3.8% AUV; weighted scorecard 2.7 vs 4.2).
  3. No value was estimated, extrapolated, or "estimated from memory." Where a cell could not be confirmed, it is blank (city cells) or flagged (F-01…F-20).
  4. Inline source links are provided on the same row as each fact; the master list is Sources & Verification.
  5. Verification date: 2026-11-06. Numbers revise; re-verify before any transaction.

Privacy & data protection (highest priority, per owner mandate)

  • No personal information is published on this site. Owner name, entity, property address, APN, rent, NOI, loan balance, purchase price, and basis appear only as [PLACEHOLDERS].
  • No lease documents, appraisals, or financial statements were requested, uploaded, or committed. If any are ever added to the repo, they must be encrypted or kept out of Git entirely (the repo is public).
  • Personal/financial data used during analysis stayed in the working session; only anonymized conclusions are published.
  • This site contains no analytics, cookies, forms, or trackers; it is a static site with no data collection.
  • Placeholders are intentional: do not "helpfully" fill them from private records into public files. Internal use only with real values kept in the owner's secure vault.
  • Git history contains only these pages and placeholder text — no personal data has been committed at any point (verified by reading the diff of this branch).

Repository review (line-by-line) — method

  • Files enumerated via git ls-tree -r origin/main: only README.md existed at review time; working tree clean; remote origin = github.com/wingbangboozle1-lang/Jack2; default branch main; repo public; GitHub Pages legacy build from main root already active.
  • README content verified byte-level ("# Jack2\n", 7 bytes) — contains no requirements list; see Flagged R-01.
  • Repo settings checked via GitHub API (Pages, visibility, default branch). No other branches, tags, releases, issues, or PRs existed at review time.
  • Irregularities and actions are recorded on Flagged for Review (R-01…R-07).

Limitations & disclaimers

  • No site inspection, appraisal, environmental, or structural review was performed.
  • Lease-specific economics are placeholders; the framework, not the $, is the deliverable until the owner plugs in actuals.
  • Forecasts beyond 2026 are labeled assumptions; LAEDC projections are point estimates with error bands.
  • Cap rates and commissions are private-market values, flagged unverified.
  • Not legal, tax, accounting, appraisal, insurance, or investment advice. Consult licensed California professionals before any sale, exchange, or renewal.
  • This site is provided "as is"; source agencies revise figures; re-verify at the links provided.

Maintenance

  • Refresh cadence: quarterly (EDD, Port of LA) and annually (Census QuickFacts December refresh, BEA December county release) — owner or advisor to update, or re-task this analysis.
  • Any figure changed on this site must be edited against this protocol: read source → edit row → update "Prepared" date → commit.
  • Flagged items F-01…F-20 should be resolved or re-flagged at each refresh.
