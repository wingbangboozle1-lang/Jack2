Suggestions — review first, implement later

Every suggestion below is a proposal, not a decision. Nothing on this page is implemented. The reviewer walks each item through the workflow, marks it here (selections are stored only in this browser’s localStorage — nothing is sent anywhere), and implementation starts only after acceptance, tracked in COORDINATION.md.

  1. Proposed (owner: preparer (this session)) — Suggestion documented with impact, effort, risk and the decision it enables.
  2. Under Review (owner: owner / advisor) — Reviewer reads the suggestion, asks questions, and records comments on the suggestion's row (client-side notes or offline).
  3. Accepted (owner: owner) — Reviewer marks accepted; a scoped task is logged in COORDINATION.md before any work starts.
  4. Rejected (owner: owner) — Reviewer marks rejected with reason; suggestion stays on the page for the record, marked rejected.
  5. Deferred (owner: owner) — Reviewer marks deferred with a trigger to revisit (e.g., 'after exact lease date confirmed').
Suggested review order: G02 (exact lease) → G04 (CPA after-tax) → G06 (hazard/insurance) → G03 (ULA jurisdiction) → G08 (renew-first negotiation) → then the rest. The decision-critical four unlock the sell-vs-renew analysis; the site-health items (G10–G12, G14) improve the workbook itself.
