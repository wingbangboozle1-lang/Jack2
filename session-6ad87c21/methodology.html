Method

Method and limitations

The verification rules, how the model was tested, two defects found and fixed during the build, and what would falsify the recommendation.

The rules this workbook follows

  1. A value is published only if it was read from the official source on 2026-11-08 and that source is linked on the same row. Not from memory, not from a summary, not from another dashboard in this repository.
  2. If no official value exists, the cell is blank. Nothing is inferred, interpolated, annualised or copied from an aggregator. The row appears on the Flagged for Review page with what to obtain.
  3. Computed values are labelled computed, cite the official series they are computed from, and show the arithmetic in the note.
  4. Assumptions are labelled assumptions and are never presented as observations. All 21 of them are published with the range tested.
  5. The build fails if a verified row lacks a source, if an unverified row carries a value, if an internal link is broken, or if a possible personal identifier appears. See scripts/verify.py.
  6. Privacy overrides convenience. If a fact cannot be published without identifying the owner, the parcel or the tenant entity, it is not published.

How the review was actually done

The session opened each official document, read the specific table or paragraph, and recorded the value with the document it came from. Where a retrieval returned something unexpected, that is recorded rather than smoothed over: for example, a Census QuickFacts request for the county returned national figures on one URL form, which is why the county rows here cite the separate county slug and why the county education rows are blank instead of filled from the national table.

How the model was built and tested

  • Six strategies, each carried to 2040 so the comparison is like-for-like.
  • All figures normalised to $100,000 of in-place NOI, so the workbook never needs the private rent.
  • A deterministic engine across Bear / Base / Bull, a 10,000-trial seeded Monte Carlo, a seven-column sensitivity grid, a five-point cap-rate break-even, and eight robustness stress cases.
  • The ranking metric is the certainty equivalent at CRRA = 2, which penalises downside — not the mean, which rewards it.
  • Two defects were found and fixed during the build and are recorded here rather than hidden: the hold strategies were initially taxed at their interim sale (inconsistent with the exchange strategies), and the Monte Carlo seed initially used Python's randomised hash(), which would have made the published output irreproducible.

What would falsify the recommendation

  • A verified cap rate materially different from the 6.00% base — for example a broker opinion of value implying 5.25% or 7.25%.
  • Lease terms that give the tenant a below-market fixed-price renewal option, which converts the option into a liability rather than an asset.
  • A corporate guaranty or a letter of credit that removes the franchisee credit risk.
  • Evidence of redevelopment value in the land that exceeds the net-lease value.

Reproduce everything

python3 session-6ad87c21/scripts/model.py       # deterministic + 10,000-trial Monte Carlo
python3 session-6ad87c21/scripts/build_site.py  # all 14 pages
python3 session-6ad87c21/scripts/verify.py      # source, blank-value, link and PII checks

Python 3.11, standard library only. No network access is needed to rebuild, and the model output is deterministic across runs.

Scope and limitations

This is internal decision support for one owner. It is not an appraisal, not tax advice, not investment advice and not legal advice. It does not value the parcel; it values a dollar of net operating income. The address, rent, basis, loan terms and lease itself were not supplied and are not guessed at. Before relying on any number here, obtain an appraisal or broker opinion of value, read the lease, and take tax advice from a CPA who has seen the basis schedule.
